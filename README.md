# superchart

## Запуск и кэш скринера

Запускать из корня проекта:

```sh
python -m superchart.run
```

Эта же команда указана в `Procfile`. Она запускает Streamlit и фоновое обновление
скринера **внутри одного web-dyno**, без отдельного worker, Scheduler и базы данных.
Первый запрос выполняется при запуске, последующие — через 60 секунд после завершения
предыдущего. Обновление работает, даже когда страницу скринера никто не открыл.
При завершении приложения launcher останавливает Streamlit и обновление.

Переменные окружения (локально можно задать в `.env`, в Heroku — в Config Vars):

| Переменная | Назначение |
| --- | --- |
| `APIMOEX_TOKEN` | Токен MOEX, обязательный для получения котировок |
| `PATH_TO_DATA_FOLDER` | Папка с `last_prices.p` и `div_table.p`; по умолчанию `data/` проекта |
| `SCREENER_REFRESH_SECONDS` | Пауза между обновлениями, по умолчанию 60 секунд, минимум 10 |
| `SCREENER_CACHE_PATH` | Путь к локальному JSON-кэшу; по умолчанию `.cache/screener.json` |
| `PORT` | Порт Streamlit, по умолчанию 8501; Heroku задаёт автоматически |

Скринер сразу читает последний успешный **готовый расчёт** и показывает время данных
MOEX. Открытая страница перечитывает кэш каждые 30 секунд. Переключение фильтров не
вызывает запросов к MOEX. Расчёт использует те же цены предыдущего дня и дивиденды,
что раньше; файлы `last_prices.p` и `div_table.p` необходимо обновлять как обычно.

Таймаут, HTTP-ошибка, некорректный или пустой ответ не затирают кэш. Запись атомарная:
страница не прочитает наполовину записанный файл. Старый результат остаётся доступным
без срока удаления; при длительном отсутствии обновлений выводится предупреждение.
Если кэша нет, показывается ошибка. Резервной таблицы из исторических файлов нет.

Локальный кэш теряется при перезапуске/деплое Heroku; после этого нужен успешный
ответ MOEX для его заполнения. Каждый web-dyno имеет свой кэш. Это соответствует
[модели файловой системы Heroku](https://devcenter.heroku.com/articles/dyno-isolation#ephemeral-filesystem).
Спящий или остановленный dyno не обновляет данные. Для обновления без посещений
приложения dyno должен оставаться запущенным. Отдельный worker или Scheduler здесь
не подходит: его локальные файлы не видны web-dyno.

Обычный `streamlit run superchart/moex_stocks.py` не запускает фоновое обновление;
используйте `python -m superchart.run` и локально, и на Heroku. Дополнительных
сервисов для деплоя не требуется.

Проверки (после установки зависимостей и `pytest`):

```sh
python -m pytest -q
```
